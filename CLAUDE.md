# Master Baiter

A troll platformer ("rage game") in plain browser JS: 3 modes (single, multi, special = chained co-op) × 40 levels. It's dressed as a pixel-art dungeon, "The Descent": knights go down through a castle for treasure. Every 10 levels is a deeper area. Player-facing docs and credits are in `README.md`.

## Verify every change

1. `node tests/solve.js` must end `errors: []` and `OK: 123 checks`. It plays every level with a bot. It runs without three.js, canvas or audio, so it only proves gameplay.
2. For anything visual, take a screenshot and look at it: `tools/shot.sh out.png "<query>"` (the query options are listed at the top of `tools/preview.html`). Errors and `FLOW` lines land in `out.png.log`. Phone layout: `SIZE=844,390 DPR=3 tools/shot.sh p.png "level=1&touch=1"`.
3. If `index.html`'s `<body>` changes, make the same change in `tools/preview.html`.
4. `node tests/net.js` must end `OK`. It runs two copies of the game online through `server/relay.mjs`'s `Room` class (fake sockets with lag) and checks that they stay identical tick for tick. Run it after any change to 2-player gameplay or input.

## Hard constraints

- **Opening `index.html` directly from disk (file://) must work: no build step and no server.** So: classic `<script>` tags (no ES modules), data shipped as JS (`js/fx-data.js`, not JSON), and three.js pinned to the r159 single-file UMD build in `js/vendor/` (r160+ is modules only). Fonts and images load fine from file://.
- **Cutscenes are optional.** `window.Cutscenes` is `null` without WebGL or three.js (always the case in tests). Then `playCut(id, then)` just calls `then()`. Keep the game fully playable on that path. (The boss intros and defeats are in-level and drawn by the game, so they always play.)
- **Gameplay readability beats decoration.** Sprites are drawn to their exact hitboxes. Hazards look identical in every area. Real and fake portals use the same sprite (that's the joke). A linked block shows the colour of its button. Background decor must never look like a hazard.
- **Reduce flashing (`save.calm`: F key, or SETTINGS on the title screen).** Any new shake, blink, strobe or flash must check `save.calm` and tone itself down, as the existing ones do: no screen shake, a steady laser warning, a dim reveal flash, and the lights-out flicker turned into a half-dim reveal.

## Rendering rules (js/game.js)

- Draw code works in **VW units** (960×540, `TILE` = 30). The canvas is **480×270**, so one art pixel = `PX` = 2 units. CSS scales the canvas by a whole number with black bars (`resize()`); it never smooths.
- Keep art on the pixel grid: `R(x,y,w,h,col)` (snapped rect), `r()` (art-pixel rect around a translated origin, used for sprites), `sn()` (snap a value). Avoid `arc`, `roundRect` and `shadowBlur`: they blur at this resolution.
- Text goes through `text(str, x, y, size, color, align, _, outline)`. Sizes snap to the BoldPixels native 16, 32 or 48 px (≤28 → 16px, ≤60 → 32px, else 48px). The font has no `✕ ☠ ≡`: `✕` is mapped to `×`, death counts use `skullIcon()`, and the touch menu button says "ESC".
- Areas: `areaOf(levelIdx)` = `floor(idx / 10)` → `AREAS[0..3]` (Upper Halls, Crypt, Flooded Depths, Molten Core). This holds in every mode. Each area's wall (`bgArt`) and block tiles (`tileArt`) are painted once and cached.
- pixelfx effects: `drawFx(name, t, x, y)` with its pivot at x, y; one-shots via `spawnFx`. To add or recolour one, edit the list in `tools/build-fx.mjs` and run it against a pixelfx checkout (`git clone https://github.com/patch-gg/pixelfx`). The script rewrites `assets/fx/*.png` and `js/fx-data.js`; don't edit those by hand.
- Menus share `panel()` (bevelled stone, gold frame when selected) and `menuBg()` (dimmed wall with two torches).

## Story and cutscenes

- Triggers: a mode started at level 1 (Enter on the mode screen) → `intro`. `game.next()` going into level 11, 21 or 31 → `area1`, `area2` or `area3`. Going past the last level → `ending` (the mimic), then the `end` screen. Picking a level from the level select never plays a cutscene.
- `js/cutscenes.js`: voxel scenes built with `builder()` (boxes merged into one mesh), drawn at 480×270, then posterized and ordered-dithered in a shader pass. A scene is `{ dur, update(t), overlay(t, ui) }`. The game draws the frame, then calls `overlay` with `cutUI` (bars, caption, label, shout, fadeOut, card) and draws the SKIP button. Input in the first 0.5s is ignored.
- The castle scene is shared by the title screen and the intro. Anything the intro adds to it must be removed in `done()`; a chain left behind on the path was a real bug. The other scenes are freed in `Cutscenes.end()`.
- Area previews: `STATIONS[n]` lists 4 looping hazard dioramas per area. The `PITS` stations get a hole cut in the floor.

## Death messages and knights

- `kill(p, cause, src)` takes the object that killed (spike, saw, laser, block). `deathKind()` turns that into a key of `DEATH`, the message pools; `KILLER` names it for the "3 in a row" streak line. A new trap or kill cause needs a pool, or it falls back to `other`. A fake or dropped floor beats whatever was under it.
- Knights are local profiles: `ragebait.knights.v1` holds the list, and each knight's save sits at `ragebait.save.v1:<id>` (knight 0 uses the old key, so old saves carry over). `useKnight()` swaps the contents of the shared `save` object. `save.best` (furthest level, never lowered by strikes or admin skips) feeds the leaderboard.

## Bosses

- Single-player levels 10, 20, 30 and 40 are boss fights, all in `js/bosses.js` (levels.js only calls `BOSSES.<id>.build(L)`): The Warden, The Undertaker, Old Gnasher, The Mimic. Multiplayer and chained finales are still the old levels. The design doc (https://claude.ai/artifact/CrXPnC7XVqjxoQ579MdqJ9) describes the first, easier version.
- Each boss is `{ build(L), draw(b, L, t, D), lit?(b, L, t, D) }`. `build` makes the arena, the boss, its moves and both cutscenes; `draw` paints it with `D`, the drawing kit game.js passes in (`D.at`, `D.r` in art pixels, `D.R`, `D.disc`, `D.saw`, `D.crate`, `D.door`, `D.calm`). `lit` draws over the darkness (the Undertaker draws everything there).
- The loop: you can't attack. Each boss gets stunned by one of its own attacks turned against it (the Warden charges into a wall or takes falling masonry; the Undertaker's soul orb is stomped back into it; Gnasher lunges through a spiked anchor; the Mimic leaps past you into lava, or chokes on you after you mash out of its mouth). The Mimic's phases 2 and 3 are the exception: it flies, and only THE LAZER hurts it (below). Touching a stunned boss starts the STRIKE quick-time event; a win is one hit. 6 hits in 3 phases of 2 (`hp: 6, perPhase: 2`).
- One run: `L.boss()` gives the knight `LIVES` (5) lives, hearts add more up to `MAX_LIVES` (9). Any hit (boss, trap, failed grab) goes through `kill()` → `hurt()`: the death line plus lives left, a knock back (or back to `p.safe`, the last plain ground, after a fall or a pit), and 1.6 s of blinking (`p.hurtT`) in which only a stunned boss (to strike it) and `stompable` attacks still react. The last life ends the run and the next one starts at phase 1: no checkpoints (`game.ckpt` is only set by the preview's `&phase=`). Lost lives don't count as deaths, so the seed holds for the whole run.
- Arenas (bosses.js helpers): every arena has two low platforms, a middle one that pops its spikes if you stand on it 1.2 s (`camp()`), a crumbling one that grows back (`regrow()`), a fake one (`solid: false`, looks the same) and `loot()`, which pops a pickup on a free spot every few seconds (it fades after 7 s, three at most, its own random stream). Pickups (`L.pickup()`, `take()`): heart, boots (speed 5 s), sword (parries one hit: `parried()` → `b.onParry`, a parried melee attack stuns the boss), feather (double jump 8 s), candle (crypt: more light). Fakes look the same but don't sparkle: `bite` (costs a life), `slow`, `invert`, `dark`. The Mimic's table is mostly fakes.
- Warnings and feints: every attack shows `L.mark()` (a red zone over exactly its hitbox, filling up over the wind-up, drawn over the darkness) before it hurts; the Undertaker's wind-ups are longer and its bones and hands come out of whatever you stand on. Each boss fakes a stun (Warden `playdead`, Undertaker `collapse`, Gnasher `playdead`, Mimic `faking`): it looks stunned, but its eyes stay lit, and touching it is a grab or a bite. The Warden reaches the scaffolds too: it vaults up onto yours (then sweeps along it), lobs its halberd onto it, and its thrust reaches the high bridge, so camping up there doesn't work. Plus a fake-out per boss: the Warden's charge that skids to a stop, the Undertaker's lane with no skulls and its dud orb (no glow; stomped, it bursts into skulls), Gnasher's lunge that stops and re-aims, the Mimic's dash that stops short into a tongue.
- Engine pieces (game.js, on `Level`): `boss(o)`, `hitBoss(b)` (hit-stop, phase), `hit(h)` adds an attack hitbox to `L.hz` (a rect, or a circle with `r`; `h.atk` picks the death pool `'<id>:<atk>'`, `h.onTouch` can grab instead of kill), `startQte({ keys | mash, time, label, slow, onWin, onFail })`, `playCine(scene, then)` / `endCine()` (in-level cutscenes: the world holds still, JUMP / ENTER / ESC / a tap skips after 0.5 s, no deaths), `freeze(sec)`, `wind` (a current), `atStart(fn)`, `firstVisit(id)` / `markSeen(id)` (intros play on a knight's first visit only; `save.seen`). Boss cutscenes are drawn by the game itself, so they work without WebGL (unlike js/cutscenes.js).
- The Mimic, the final exam. Phase 1 on the ground (crate disguises, WRONG WAY hexes: a second's warning, then `L.invertT`). Phase 2 (`sprout`): wings, it flies (`flyUpdate`): bullet-hell coin barrages (`bullet()`, `h.shootable`): rings, spirals, aimed fans, a rain with one marked gap (always over solid floor), swoops. Phase 3: the same in the dark (`L.dark`; it, its coins, the lava and the rock's edges are drawn in `lit`), the floor turning to lava every 7-10 s (`lavaTick`, atk `rising`, marked first; a hit puts you back on the middle rock via `src.respawn`), more hexes. In the air only THE LAZER hurts it: a pickup (`L.pickup('laser')`) that turns up on your stretch of floor within ~2 s whenever you have none; its aim sweeps the upper half (`p.laser.a`), DOWN fires (`fireLaser()`: a ray that calls `b.onBeam`, else `hitBoss`, and burns `shootable` projectiles). Input: `fire` = ↓ / S, gamepad down, and a touch ▼ button (in index.html and tools/preview.html) shown only while you hold a lazer. Fairness: one barrage at a time (it waits for most coins to clear), no rain while the lava is up, lasers never on the spiked perch.
- Death lines and streak names for every attack live in bosses.js (`B.lines`, `B.killers`); game.js merges them into `DEATH` / `KILLER`.
- Bosses move erratically from a random source seeded by the death count, the level and the checkpoint (`kit()`): every attempt differs, but never `Math.random`, so a run can be replayed. Fairness rules found the hard way: one stream of projectiles at a time; a stunned or hit boss drops whatever it had cast (`K.clear()`); a boss that just got hit or roars can't hurt you for a moment; no attack spawns on top of you; no two floor threats at once (the Warden won't stomp, charge or leap under falling masonry; the Undertaker won't throw skulls while bone spikes are up, or raise bones under a rolling orb before phase 3). Pace: every idle gap is scaled by `PACE` (0.4) and the filler moves (walk, hop, feint, drift, swim, sit) are rare, so you're dodging most of the fight. The HUD shows the boss's name over a health bar with a notch per phase.
- Tests: `tests/solve.js` has a bot per boss (shared helpers `qteBot`, `planSafe` (simulate the knight's run / jump / hop / jump-later plans against projectiles and timed or moving rects), `orbJump`). They play like a player: start on the default attempt, and after a lost run go again from phase 1 (a new seed), up to 8 runs. The ground bots ignore platforms and pickups; the Mimic's air bot (`mimicAir`) climbs rock (`climb`), fetches lazers and fires them, hops pits, and picks the dodge the coins come least close to (`planSafe` reports `out.clear` and `out.land`, and simulates speed boosts `p.mul` and short hops `p.cutAt`). The runner swaps left/right for the bots while a boss's hex inverts the controls. With 5 lives a perfect-information bot wins a run about: Warden 100%, Gnasher 100%, Undertaker 60%, Mimic 35% (all its losses in phase 3) (20 attempts each, 2026-11-28, after the flying Mimic and the Warden's scaffold attacks). Check over many attempts before touching difficulty, not only the default one.
- Preview: `?level=10&seen=1` (skip the intro), `&phase=3`, `&wait=STEPS` (run with no input), `&tell=1` (run until an attack warning is up), `&at=X,Y` (put the knight there), `&laser=1` (hand it the lazer), `&defeat=1&t=2` (the defeat cutscene), `&qte=strike|mash`.

## Online play

- Multiplayer and Special go through the `net` screen first: OFFLINE (the old local co-op, `playMode()`), HOST ONLINE (random 4-letter code) or JOIN ONLINE (type the code; `askCode()` uses `prompt()` on touch).
- **Lockstep** (`netSteps()` in game.js): both browsers run the whole game and send only inputs. A tick's input is 7 bits (left, right, jump held, fire held, jump pressed, fire pressed, R), plus bits 7 and up for a level pick (index + 1; if both players pick on the same tick, the host's wins). It's queued `net.delay` ticks ahead and only runs once both players' inputs for that tick are in. The host pings 3 times and sets the delay to half the slowest round trip in ticks + 10, then sends `go`. Pacing in `netSteps()` caps catch-up at about one extra tick a frame and runs at 3/4 speed while fewer than 5 frames of the partner's inputs are in hand (half speed was worse: one side slowing makes its inputs late for the other, and the slowdowns feed each other). Running flat out to the newest input made every late packet a freeze, then a jump of up to 12 ticks; players saw stutter whenever someone moved. A simulated Philippines–Tokyo link (jitter plus TCP stalls) went from 11% frozen frames and 63 jumps to 1% and none. Re-measure that way before retuning (mode, its saved level, delay); better, replay recorded latencies of the live relay (see Lanes). Online, every device writes to input slot 2 (`ctl[2]`, `pressed[2]`); `ctl` and `pressed` 0 and 1 are set from the queues each tick.
- **So the 2-player simulation must stay deterministic.** No `Math.random`, wall-clock time or per-knight save data (`L.deaths`, `save.*`) in anything multi or special levels run. Cosmetic randomness (death lines, particles, the lights-out flicker) is fine. Anything that changes the game from outside a tick has to travel as an input (like R) or it desyncs. The admin N skip is off online and god mode is ignored. Esc opens the level select through `netMenu()`: that side stops stepping, so the partner stalls, and a `menu` message lets the partner's HUD say why. A pick goes out as input (`net.pick`), and both sides run `game.start()` on the same tick. `net.top` (the furthest of both players' progress when the session starts, the same on both sides) is the floor for `game.unlocked()`. X or the LEAVE button (`NET_LEAVE`) on that screen leaves the room.
- **Lanes** (`netLanes()`): at `go`, each player opens two spare sockets (`?lane=1`, `?lane=2`). Input messages (one per 4 ticks) and `sync` go out on all three, and the first copy of a tick wins; copies for ticks already run are dropped. Measured from this machine, one connection's slowest 1% one way was 200–1700 ms, the first of three 120–200 ms, because each connection takes its own route and TCP stalls behind a lost packet. `sync` must travel with the inputs: if it only went on the main socket, the guest could get the inputs for tick k over a lane first and run past the restart. Control messages (`go`, `h`, `menu`, pings) stay on the main socket. Relay: lane k only talks to the other player's lane k, and a lane closing doesn't close the room. An older relay refuses lanes (taken or full) and the game carries on over one socket. `tests/net.js` stalls both main sockets for 5 s and expects full speed.
- **Prediction** (`netPredict()`, Multiplayer only, not chained or swapped): each frame your knight is copied and stepped through your own queued inputs (`net.q[net.me]` from `net.tick` to `net.sent`) with `L.dry` set. In dry mode `stepPlayer(p, dt, { c, pr })` skips everything outside `p`: jump hooks, crate pushes, `reveal`, the lazer, sound and particles. The level isn't stepped. `drawLevel` draws `net.pred` in place of your knight; the simulation never sees it. Anything new in `stepPlayer` that touches the level needs a `!dry` guard. The player-on-head check compares `idx`, since the prediction is a copy.
- **SMOOTH / SNAPPY** (`save.snappy`, a row on the `net` screen): `go.d` is `[host delay, guest delay]`, because each player sends its own inputs ahead by its own amount (ticks are absolute, so they needn't match). SNAPPY is 6 ticks less. The partner then has less cushion, so the pacing slows it more often.
- Desync guard: the guest sends `netHash()` (level and the knights' positions) every 60 ticks. On a mismatch the host schedules `sync` at tick `net.sent`, which the guest can't have passed yet, and both restart the level on that tick.
- Relay: `server/relay.mjs` (Durable Object `Room`, hibernation API): one host, one guest, plus two lanes each (tags `host-1` etc.). It sends `peer` when the guest joins, `left` to the other player when either leaves (which closes the room), and `err` for a code that is taken, missing or full. `wrangler.jsonc` serves the game's files from the same Worker, copied into `dist/` by its `build` step (git-ignored). Don't point `assets` back at the repo root: `wrangler dev` restarts on any change in the served folder, including `.git` and `.wrangler`, and a restart drops every room. The game is deployed on Cloudflare Pages (from `main`), which can't run the relay, so `NET_URL` in game.js points at the deployed Worker (`wss://master-baiter.gungonjohnrevel.workers.dev/net`). Only pages on localhost use their own origin (`wrangler dev`). Relay changes need `npx wrangler deploy`; a push alone only updates Pages. A new top-level file the page loads must be added to that copy command.
- Preview: `?state=net&mode=multi[&room=ABCD]`, `?level=4&mode=multi&online=1` (the online HUD, stalled), `?state=select&mode=multi&online=1` (the online level select), `?state=net&mode=multi&sel=3` (a lobby row selected).

## Music

`SONGS` in game.js is a small step sequencer. Each channel (`lead`, `bass`, `arp`, `drums`) is a list of bars, each exactly 16 space-separated steps: a note like `c#4`, `.` for a rest, `-` to hold. Drums use `k`, `s`, `h`. Channels loop on their own lengths. `music.want(id)` in the main loop picks the song: `title` (menus and intro), `area0`–`area3` (levels and area cutscenes), `boss0`–`boss3` (while that area's boss is alive), `ending`, `win`. `M` mutes music and sound effects together.
